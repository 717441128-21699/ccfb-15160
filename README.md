# 高空抛物溯源分析平台

纯前端（TypeScript + WebGL2）高空抛物检测与溯源工具。监控视频全程在本机浏览器内处理，不上传任何服务器；通过楼面透视标定把下落轨迹反推到具体楼层与户号，并生成可打印的取证报告。

## 功能页面

| 页面 | 能力 |
| --- | --- |
| 楼栋标定 | 导入截图/视频抽帧，拖拽楼面四角，按楼层数×户数生成透视网格，一次标定复用同机位所有视频 |
| 视频分析 | WebGL2 实时检测 + 多目标跟踪 + 抛物线反推，可调阈值/昼夜/风偏，实时叠加轨迹与抛出点 |
| 事件列表 | 全部检出事件，含楼层/户号概率分布、运动学特征、轨迹复核，可删除误报 |
| 取证报告 | 溯源结论、轨迹证据图、概率分布、运动学分析，可打印/另存 PDF、导出 JSON |
| 合成测试 | 按物体类型/风速/红外/干扰物合成带真值的测试视频，自动跑全链路并核验指标 |

## 技术架构

```
视频帧
  └─ WebGL2 检测管线（src/gl/）
       亮度 → 背景更新(EMA乒乓) → 帧间差∨背景差 → 阈值 → 腐蚀/膨胀 → readPixels
       └─ CPU 两遍法连通域（并查集）
  └─ 多目标跟踪（src/core/tracker.ts）
       速度预测 + 贪心最近邻关联，规则分类器区分 抛物/雨滴/飞鸟/树叶
  └─ 抛物线反推（src/core/origin.ts）
       轨迹→楼面网格坐标，稳健二次拟合 + 离群点剔除，回溯出手点，映射楼层/户号
  └─ 事件合并、持久化（localStorage）、取证报告
```

关键设计：

- **无 GL 反馈环**：背景纹理双缓冲乒乓，背景更新与差分分离，避免同一纹理读写。
- **帧间差为主**：帧差天然无 EMA 鬼影，背景差仅在物体悬停时兜底，形态学膨胀桥接前后边。
- **像素坐标一致**：跟踪、特征、反推全程使用分析分辨率像素坐标，归一化仅在网格映射边界转换。
- **双抽帧模式**：`fast`（快放+rVFC，适合真实连续视频，吞吐高）/ `seek`（逐帧定位，兼容性好、结果可复现），`auto` 在 rVFC 异常时回退。
- **反推稳健化**：RANSAC 式离群点剔除 + 顶点/短外推双候选择优 + 户号取水平中位数抗风偏。

## 开发与运行

```bash
npm install
npm run dev        # 开发服务器
npm test           # 单元测试（21 个：数学/标定/分类/反推/事件合并）
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
```

端到端验证（需本机 Edge，使用 playwright-core 驱动无头浏览器）：

```bash
npm run preview -- --port 5317 --strictPort   # 终端 A
node scripts/e2e-check.mjs http://localhost:5317/   # 终端 B
```

## 验收指标现状（诚实说明）

在无头 Edge + SwiftShader 软件渲染、MediaRecorder 合成视频的测试环境下，多轮 E2E 的典型结果为：

- **召回率**：约 33%~83%（随编码非确定性波动），规则分类能稳定排除绝大多数雨滴/飞鸟/树叶。
- **楼层误差**：匹配上的事件平均绝对误差约 1.5~3 层，≤1 层占比约 25%~67%。
- **户号判对率**：约 0%~50%。
- **分析速度**：seek 模式约 2× 实时；fast 模式设计目标 ≥12× 实时（真实连续视频可达，无头合成视频因 rVFC 丢帧回退 seek）。

**距需求目标（楼层误差≤1 层 100%、户号≥90%、1 小时素材 5 分钟内）尚有差距**，主要受限于：

1. 纯规则 + 帧差检测在高压缩合成视频上受编码块噪声干扰，产生碎片轨迹与假阳性；
2. 无头环境 MediaRecorder 视频的 rVFC 回调不可靠，被迫使用较慢的 seek 抽帧；
3. 检测轨迹的质心抖动经透视放大后影响楼层/户号定位精度。

反推数学本身在精确物理轨迹（含 ±8px 噪声）的单元测试中楼层/户号误差为 0，见 `test/origin-accuracy.test.ts`，瓶颈集中在检测阶段的轨迹质量，而非反推算法。

## 已知限制与后续方向

- 规则分类器对未见运动模式泛化有限，生产环境建议接入轻量 CNN 检测/分类模型（WebGL2 可承载推理）。
- 单高斯背景建模对光照突变敏感，可升级为 MoG 或 ViBe。
- 真实监控视频建议用 `fast` 模式；无头/损坏录像用 `seek` 模式。
- 标定依赖人工四角对齐，相机移动后需重新标定。
